# Статус DentBoard — внешняя проверка доступности

Страница: **https://genrihbag.github.io/dentboard-status/**

## Зачем этот репозиторий существует отдельно

28.08.2026 боевой сервер DentBoard был недоступен снаружи **2 часа 29 минут** — не пускал по SSH,
не отдавал сайт, не мог `git pull`. При этом машина была жива и здорова: 6,3 ГБ свободной памяти,
нагрузка 0,28, все 440 замеров внутреннего наблюдения на месте, база в приватной сети отвечала.
Отказала публичная сеть. Владелец узнал об этом утром, открыв сайт, и вернул машину ручной
перезагрузкой — то есть отказ длился ровно столько, сколько владелец спал.

**Внутреннее наблюдение этот класс отказов не видит по построению.** Prometheus опрашивает
экспортеры по внутренней docker-сети и наружу не выходит вовсе: в окне отказа он рапортовал полное
здоровье — и был прав, изнутри всё работало. Улучшать его бессмысленно; нужна точка наблюдения
**вне** проверяемой системы.

Отсюда всё устройство: проверка запускается на машинах GitHub, история хранится здесь, страница
публикуется на GitHub Pages. Ничего из этого не размещено на серверах DentBoard, поэтому работает
ровно тогда, когда нужно, — во время их недоступности.

## Что здесь есть

| файл | что делает |
|---|---|
| `targets.json` | что проверяем — единственный список, правится только здесь |
| `check.mjs` | опрашивает цели, обновляет историю, шлёт тревогу в Telegram |
| `render.mjs` | собирает `index.html` из истории |
| `.github/workflows/check.yml` | запуск раз в 5 минут |
| `data/history.json` | текущее состояние и события |

## Уведомления

Тревогу шлёт **сам workflow**, напрямую в `api.telegram.org`, **минуя серверы DentBoard**. Слать
сообщение о недоступности сервера через этот же сервер значит получить уведомитель, который
молчит вместе с тем, о чём должен уведомить.

Настройка — два секрета репозитория (Settings → Secrets and variables → Actions):

- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather
- `TELEGRAM_CHAT_ID` — куда слать

Без них проверка работает, а сообщения не уходят, и это **печатается в журнале прогона**:
«телеграм не настроен» — чтобы «не настроено» не выглядело как «отправлено».

## Чего этот монитор НЕ делает

**Не обнаруживает мгновенно.** Минимальный интервал расписания в GitHub Actions — пять минут, и
запуски у них задерживаются, а при нагрузке пропускаются. Реальная задержка — от 5 до 15 минут.
Для отказа длиной в часы этого достаточно; обещать «узнаете через минуту» нельзя.

**Не чинит.** Лечение — сторож сети на самом сервере (`infra/netwatch` в основном репозитории):
после нескольких неудач подряд он переподнимает сеть, потом перезагружает машину. Монитор
**сообщает**, сторож **лечит**; ни один не делает работу другого.

**Не заменяет внутреннее наблюдение.** Prometheus видит то, чего не видит монитор: расход памяти,
глубину очередей, задержки запросов, молчание планировщика. Они дополняют друг друга — каждый
слеп ровно там, где зряч второй.

## Проверить, что монитор вообще работает

Зелёная страница ничего не доказывает, пока не показано, что монитор умеет краснеть. Добавьте в
`targets.json` заведомо мёртвую цель, дождитесь прогона и убедитесь, что пришла тревога:

```json
{ "name": "ПРОБА", "url": "https://dentboard.ru/этой-страницы-нет-и-не-будет", "expect": 200 }
```

Ожидается: строка `🔴 ПРОБА` в журнале прогона, сообщение в Telegram, красная плашка на странице.
После проверки цель убрать. Без этого «всё зелено» означает только то, что скрипт запускается.
